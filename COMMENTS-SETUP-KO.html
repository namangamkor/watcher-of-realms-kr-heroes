나만겜 워처 오브 렐름 위키 · v2.12.0 · 2026-09-11

영웅별 후기와 관리자 화면
설치 안내

코드 작성과 로컬 검증을 마쳤습니다. 실제 worwiki.kr에 적용하고 사용하려면 아래 Cloudflare 설정이 필요합니다.

설정이 없거나 COMMENTS_ENABLED가 false이면 영웅 페이지의 댓글 영역은 열리지 않습니다. 초기 설정을 마친 뒤 마지막 단계에서 활성화하세요.

1. 사이트 파일 반영

  1. 기존 사이트를 업데이트할 때는 patch.zip을 풉니다.
  2. 기존 GitHub 도감 저장소의 같은 경로에 파일을 덮어쓰고, 새 파일도 함께 추가합니다. _worker.js는 기존과 같이 최상위에 둡니다.
  3. 기존 Cloudflare Pages 배포 방식으로 반영합니다. 추가 npm 설치나 빌드 명령 변경은 필요하지 않습니다.

패치본에는 변경된 파일만 들어 있습니다. 전체 백업본은 이미지까지 포함한 사이트 전체입니다. 앞으로 실제 이용자가 작성하는 댓글 데이터는 D1에 저장되므로 사이트 ZIP과 별도로 백업해야 합니다.

2. 댓글 데이터베이스 만들기

  1. Cloudflare에서 D1 SQL database → Create Database를 엽니다.
  2. 이름을 worwiki-comments로 지정합니다.
  3. 생성한 데이터베이스의 Console을 엽니다.
  4. 압축 파일에 들어 있는 comments-schema.sql 전체를 복사해 붙이고 Execute를 누릅니다.

테이블 4개가 생성됩니다: comments, comment_reports, comment_rate_limits, comment_moderation_log.

동일한 초기 SQL을 다시 실행해도 기존 댓글을 지우지 않도록 작성했습니다. 테이블 생성 방식은 Cloudflare D1 공식 안내를 따릅니다.

3. 기존 Pages 프로젝트와 연결

  1. Workers & Pages → 현재 영웅도감 프로젝트 → Settings → Bindings → Add를 엽니다.
  2. D1 database를 선택합니다.
  3. Variable name에 COMMENTS_DB를 입력하고, 데이터베이스는 방금 만든 worwiki-comments를 선택합니다.

운영 사이트를 설정할 때는 Production 환경에 적용합니다. 연결 변경은 재배포 후 적용됩니다. Pages D1 연결 안내

4. 로봇 확인 만들기

  1. Cloudflare의 Turnstile → Add widget을 엽니다.
  2. Widget name: worwiki-comments
  3. Hostname: worwiki.kr
  4. Widget mode: Managed
  5. 생성 후 표시되는 Site key와 Secret key를 6단계 설정에 사용합니다.

실제 발급 키를 사용합니다. 공개 테스트 키는 운영 코드에서 허용하지 않습니다. 로봇 확인은 화면뿐 아니라 서버에서도 검증합니다. 위젯 생성 · 서버 검증 안내

5. 관리자 이메일 로그인 설정

관리자는 이메일로 받은 일회용 인증번호로 로그인합니다. 방문자는 회원가입 없이 후기를 제출합니다.

  1. Cloudflare Zero Trust → Integrations → Identity providers에서 Add new identity provider → One-time PIN을 추가합니다. 최신 신규 조직에서는 이 방식이 자동으로 추가되지 않으므로 직접 선택합니다. 이메일 인증 설정 안내
  2. Access controls → Applications → Create new application으로 이동합니다.
  3. Self-hosted and private → Add public hostname을 선택합니다. 앱 이름은 나만겜 댓글 관리, 도메인은 worwiki.kr, Path는 /admin/*로 지정합니다.
  4. Allow 정책의 Include → Emails에 본인이 사용할 관리자 이메일 주소를 입력합니다. 도감 전체를 로그인 대상으로 잡지 말고 관리자 경로에만 적용합니다.
  5. 로그인 제공자는 앞서 추가한 One-time PIN을 선택합니다. 세션은 예를 들어 8시간으로 설정합니다.
  6. 팀 주소 https://팀이름.cloudflareaccess.com와 이 애플리케이션의 AUD tag를 기록합니다.

관리 화면과 관리 API가 모두 /admin/comments/ 아래에 있습니다. 앱 경로 전체가 보호되도록 설정하세요. Access 애플리케이션 생성 · 경로 설정

6. Pages 환경변수 입력

기존 영웅도감 Pages 프로젝트의 Settings → Variables and Secrets에서 Production 값을 입력합니다.

이름종류입력할 값
COMMENTS_ENABLED일반 변수처음에는 false
TURNSTILE_SITE_KEY일반 변수4단계의 Site key
TURNSTILE_SECRET_KEYSecret4단계의 Secret key
COMMENTS_SECRETSecret아래에서 생성한 64자리 값
ACCESS_TEAM_DOMAIN일반 변수https://팀이름.cloudflareaccess.com
ACCESS_AUD일반 변수5단계 앱의 AUD tag
COMMENT_ADMIN_EMAILSSecret 권장5단계에서 허용한 관리자 이메일과 동일한 주소

관리자 이메일은 Access 정책과 서버 허용 목록 양쪽에서 일치해야 합니다. 추가 운영자가 생기면 두 곳 모두 추가합니다. 관리자 인증은 서명, 발급자, 대상 앱, 유효기간을 확인합니다. 인증 검증 기준

COMMENTS_SECRET 생성

아래 버튼은 이 브라우저에서 난수를 생성합니다. 생성값을 외부로 보내거나 저장하지 않습니다.

생성한 값을 Cloudflare의 Secret에 저장하세요. 재배포 때도 같은 값을 유지합니다. 이 값을 바꾸면 기존 작성자의 본인 삭제 확인이 끊어집니다. 비밀값이나 인증번호가 보이는 화면을 공유할 때는 해당 부분을 가려주세요.

도메인은 기본적으로 https://worwiki.kr을 사용합니다. 이 주소로 운영한다면 추가 COMMENTS_ORIGIN 설정은 필요하지 않습니다.

7. 관리자 화면 확인 후 댓글 열기

  1. 파일과 환경변수를 모두 저장한 뒤 기존 Pages 프로젝트를 다시 배포합니다.
  2. 관리자 화면 열기에서 허용된 이메일로 인증합니다.
  3. 승인 대기·공개·숨김·신고 숫자가 0으로 나오고 오류가 없는지 확인합니다. 처음에는 댓글 작성이 닫혀 있다는 안내가 정상입니다.
  4. COMMENTS_ENABLED를 true로 바꾸고 다시 배포합니다.
  5. 영웅 상세 하단에서 테스트 후기를 제출합니다. 관리 화면에서 승인하기 전에는 다른 브라우저에 공개되지 않아야 합니다.
  6. 관리자 화면에서 공개 승인 → 다른 브라우저에서 확인 → 신고 → 숨김 → 삭제 흐름을 확인합니다.

로컬에서 검증한 것은 실제 Worker 코드의 동작입니다. 운영 계정의 D1 연결, 실제 이메일 수신, 실제 Turnstile 통과와 브라우저 표시 확인은 이 단계에서 진행해야 합니다.

운영할 때

  • 새 후기는 항상 승인 대기로 저장됩니다. 승인된 텍스트 후기만 공개됩니다.
  • 닉네임은 2~20자, 후기는 5~500자입니다. 각성 단계는 선택 항목입니다.
  • 같은 접속 환경과 작성자는 60초 간격, 24시간 단위 10건으로 작성이 제한됩니다. 여러 영웅에 나누어 써도 같은 제한을 적용합니다.
  • 신고만으로 자동 삭제하지 않습니다. 관리자가 확인해 숨기거나 신고를 처리 완료합니다.
  • 숨김은 다시 공개할 수 있고, 삭제는 후기와 연결된 신고를 지웁니다. 관리자 작업 이력은 별도로 남습니다.
  • 방문자는 같은 브라우저에서 본인 후기를 삭제할 수 있습니다. 쿠키를 지웠거나 다른 기기에서 작성했다면 관리자에게 삭제를 요청해야 합니다.
  • 잠시 닫으려면 COMMENTS_ENABLED=false로 바꾸고 재배포합니다. 저장된 댓글은 유지됩니다.
  • 사이트 ZIP에는 운영 DB의 댓글이 포함되지 않습니다. 댓글 데이터 백업은 D1에서 별도로 관리합니다.

스팸 장치는 자동 도배와 노출을 줄이는 역할입니다. 공개 승인 여부는 운영자가 판단합니다.

검증 범위

실제 Worker 코드와 SQLite를 사용한 14개 시나리오 그룹을 확인했습니다. 254명 영웅 페이지 연결, 승인 전 비공개, 권한 위조 차단, 타인 삭제 차단, 동시 작성 제한, 신고·숨김·삭제, 페이지 나누기와 SQL 검색이 포함됩니다.

개발자가 다시 확인하려면 Node 22.13 이상에서 node maintenance/comments.test.mjs를 실행합니다. 테스트용 데이터와 인증키는 실행 중에만 생성되며 운영 데이터로 들어가지 않습니다.

브라우저 렌더링 검사와 실제 Cloudflare 서비스 연동 검사는 아직 수행하지 않았습니다.

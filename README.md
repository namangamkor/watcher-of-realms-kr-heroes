# worwiki.kr v2.14.75 — 신규 영웅 등록 동기화

- 기준: 사용자가 2026-09-28 제공한 전체 GitHub 저장소 ZIP(v2.14.74 파일과 일치)
- 상태: 패치 제작 및 로컬 검증 완료. GitHub/Cloudflare 배포 여부는 사용자 확인 전까지 미적용.
- 변경: `heroes.json`을 영웅 정보의 기준으로 사용한다. 기존 생성 스크립트가 상세 정보와 별칭 등을 누락하던 문제를 고쳤다. 생성 시 `_worker.js`의 전체 영웅 데이터·최근 영웅 업데이트, Worker 첫 화면 카드, `index.html` 대체 첫 화면 카드, `sitemap.xml`, `app.js` 요청 버전을 함께 동기화한다.
- 기존 258명의 데이터와 이미지 경로 유지. `sitemap.xml`에 빠졌던 오켄바르·베이라시아 추가. 과거 `index.html`의 256장 대신 258장으로 맞춤.
- 발레리아(`valara`)와 발레리야(`valeriya`)는 각각 다른 영웅이며 이미지 경로를 별도로 검증했다.

## 적용

이 ZIP의 파일을 GitHub 저장소 루트에 같은 이름으로 덮어쓴 뒤 배포한다. `generate-hero-seo-assets.mjs`도 함께 저장한다. 이 ZIP은 전체 백업이 아니라 변경 파일 패치다.

## 다음 신규 영웅 등록

1. 새 이미지를 저장소에 추가하고 `heroes.json` 배열에 영웅 한 항목을 추가한다. `id`, `nameKr`, `nameEn`, `class`, `rarity`, `factions`, `memberships`(진영, 정렬 순서, 이미지 경로)를 입력한다. 공식 한국명은 확인된 값만 쓴다.
2. 최신 목록에도 나타나야 하면 **그 영웅 항목 안에** `wikiUpdates`를 넣는다. 예: `[{"id":"hero-example-new-20260928","kind":"new-hero","kindLabel":"신규영웅등록","message":"신규 영웅 등록","timestamp":1790553600}]`. `timestamp`는 초 단위 Unix 시간이다. 기존 최신 3건도 해당 영웅 데이터로 옮겼다.
3. Node.js가 설치된 컴퓨터에서 저장소 루트 기준 `node generate-hero-seo-assets.mjs --version 2.14.76`을 실행한다. 다음 패치마다 버전을 올린다. 이어서 `node generate-hero-seo-assets.mjs --version 2.14.76 --check`를 실행한다.
4. 생성된 `_worker.js`, `app.js`, `heroes.json`, `index.html`, `sitemap.xml`과 새 이미지를 **같은 배포**에 반영한다. 생성된 파일 중 어느 하나라도 빠졌다면 배포하지 않는다.

생성 스크립트는 이미지 누락, 중복 영웅 ID, 중복 최신 업데이트 ID, 자료 형식 오류를 확인한 뒤 파일을 쓴다. 기존 카드의 꾸밈 요소는 유지하며 새 영웅의 첫 화면 카드는 핵심 정보로 생성한다. 브라우저 `app.js` 로딩 후 전체 카드 UI가 반영된다.

## 검증 및 삭제

로컬 검증: 기존 258명 Worker 데이터 완전 일치, Worker/대체 첫 화면 카드 각각 258장, 사이트맵 영웅 258명과 일반 페이지 2개, 이미지 경로 존재 확인. 임시 영웅을 추가한 별도 복사본에서 259장/사이트맵 261개/최근 목록 반영 및 재실행 무변경 검증. JS 문법 검사 통과.

이번 패치에 필요한 삭제 파일은 없다. 저장소의 과거 이미지와 안내 문서는 별도 사용처 검증 전 삭제하지 않는다.
